# 票小帮 - PDF / OFD 发票管理工具

一个纯前端的电子发票管理工具，支持 PDF 与 OFD 数电票，所有文件处理都在浏览器本地完成，不会上传到任何服务器（OCR/大模型纠错为可选云端增强，默认关闭）。

**在线使用**：<https://wy133656.github.io/piaoxiaobang/>

> 想要正式域名？申请与解析步骤见 [腾讯云域名申请指引.md](./腾讯云域名申请指引.md)

---

## 功能概览

### 1. 发票台账管理（核心功能）

批量上传 PDF / OFD / **图片（手机拍照）** 发票，自动识别并生成 14 列标准台账：

| 列  | 字段      | 说明                               |
| -- | ------- | -------------------------------- |
| 1  | 发票类型    | 电子专票 / 电子普票 / 纸质专票 / 纸质普票        |
| 2  | 开票日期    | 格式 yyyy-MM-dd                    |
| 3  | 发票号码    | 20 位数电票号码或旧版发票号码                 |
| 4  | 销售方名称   | 公司全称                             |
| 5  | 销售方简称   | 自动从全称提取（去地域、去行业词、去公司类型后缀）        |
| 6  | 购买方名称   | 公司全称                             |
| 7  | 商品/项目摘要 | 提取商品分类星链（如 `*照明装置*颜色分类:白`）+ 规格型号 |
| 8  | 金额(不含税) | 合计金额（数电票）或价税合计（旧版发票兜底）           |
| 9  | 税额      | 合计税额或由价税合计反算                     |
| 10 | 价税合计    | 金额 + 税额自动计算                      |
| 11 | 费用分类    | 按摘要/销售方关键词自动分类（建设费用/办公费/福利费等）    |
| 12 | 特殊情况说明  | 按金额分级 + 类型自动生成报销附件提示             |
| 13 | 重命名后文件名 | `类型+日期+号码+简称+合计.pdf` 格式          |
| 14 | 序号      | 自动编号 + 合计行                       |

**台账特性**：

- 重复发票自动标红（按发票号码 + 发票代码比对）
- 字段不完整的发票标黄提醒
- 费用分类未识别的标记"待确认"
- 每行可点击"编辑"打开 14 字段全编辑弹窗
- 弹窗内简称/说明/文件名支持"自动生成"按钮一键重算
- 金额/税额修改后价税合计自动联动
- 一键导出带样式 Excel（标题行合并、表头蓝底白字、数字千分位、边框、自动列宽）
- **数据本地持久化**：台账自动保存到浏览器 IndexedDB，刷新/关闭页面不丢失
- **筛选与统计**：顶部搜索框 + 分类下拉实时筛选，统计卡实时显示张数/金额/税额/价税合计
- **打包下载**：按「重命名后文件名」一键批量重命名并打包 ZIP

### 2. 发票查重

- 批量上传发票（PDF / OFD），按发票号码自动比对
- 标注重复发票（红色高亮），显示重复次数
- 支持从台账一键导入查重
- 导出查重结果 Excel

### 3. 发票合并打印

- 批量上传 PDF 发票，合并到 A4 纸打印
- 支持每页 1/2/4/6/8 张排版
- 支持横向/纵向打印方向
- 可调整页面四边边距（mm）
- 可选发票边框显示
- 自动计算所需 A4 纸张数

### 4. 扩展能力（可选，默认关闭）

- **OFD 数电票解析**：原生支持 .ofd 文件（JSZip 解包 + XML 坐标还原）
- **扫描件 OCR 识别**：PDF 文本提取为空时自动调用腾讯云通用印刷体识别（每月 1000 次免费额度）
- **大模型字段纠错**：识别完成后用 DeepSeek/混元等大模型校验号码、金额、日期等字段
- **自家公司可配置**：设置弹窗修改公司全称，自动影响购买方识别与特殊说明（localStorage 持久化）

> 开通步骤见 [腾讯云开通指引.md](./腾讯云开通指引.md)

### 5. 智能发票录入（v3.0）

- 手机拍照直接上传发票图片（.jpg/.jpeg/.png/.webp/.bmp）
- 图片自动压缩（长边 2048）→ 腾讯云 OCR 识别 → AI 自动提取发票代码、号码、金额、税额、开票日期

### 6. 自动对账（v3.0）

- 导入银行流水 Excel，智能识别列头（日期/对方户名/收入/支出/发生额/余额，兼容多家银行格式）

- 未匹配项自动标记并给出原因（金额不符/名称不符/工资社保等非发票收支/跨期）
- 一键导出对账结果 Excel；支持 AI 分析未匹配原因及处理建议

### 7. 业务报表自动生成（v3.0）

- **周报**：统计上周收入/支出汇总、Top5 供应商、Top5 客户贡献、环比异常提醒（变化 >30% 且金额 ≥2000 触发）
- **月报**：月度收支汇总 + 分类占比 + Top5 客户，附上月环比
- **周一自动生成**：每周一打开页面自动生成上周周报并展示在「报表中心」（仅本地统计，不发送邮件）
- **简报一键复制**：生成格式化简报文本，一键复制，可粘贴到微信 / 钉钉 / 文档分享
- **AI 财务分析报告**：一键生成文字版经营分析（收支结构、客户集中度、异常波动解读）
- 报表数据可导出 Excel / 渲染 Markdown 版分析报告

### 8. AI 自动化财务报表 + 智能对账模板（v3.0）

- **自动取数**：直接读取本地台账数据，无需人工整理表格
- **智能出表模板**：周报/月报统一模板，财务数据自动填充
- **智能对账模板**：对账逻辑全部由算法完成（金额容差 ±0.01、公司名核心词模糊匹配、方向校验、日期窗口），替代人工逐笔核对

### 9. 四格式统一导入（v4.0 P0）

- **表格 / Word / PDF / 图片 一键导入**：发票路径（PDF/OFD/图片 → OCR）与表格路径（Excel/CSV/Word → 列映射）自动分派
- **智能列映射**：任意表头自动识别到 日期/号码/金额/税额/价税合计/供应商/分类 等标准字段，导入前弹窗预览、可手动调整映射
- **字段容错**：金额（千分位/货币符号/括号负数）、日期（yyyy年mm月dd日/斜杠/序列号）多格式自动归一
- **Word 解析**：JSZip 解包 document.xml，优先取表格、无表格降级按段落行解析
- **架构原则「独立 + 联动」**：每个功能页签自带数据导入入口、可独立使用；导入结果统一写入共享台账，对账/报表/看板随时取用，一处导入处处可用

### 10. 外部 AI 服务槽位（v4.0 P0）

- 设置面板新增「外部 AI 服务」：接口类型（OpenAI 兼容 / Anthropic）、Base URL、API Key、模型名全部由用户自填
- 协议双支持：OpenAI `chat/completions` + Anthropic `messages`（含浏览器直连头）
- 用途开关：字段纠错 / 文字报告 / 流水归类可分别开关；触发调用前提示数据将发送至所配服务商，默认零上传

## PDF 解析原理

### 文本提取

pdf.js 返回的文本片段（item）顺序与视觉顺序不一致。票小帮按以下步骤还原：

1. 遍历每个文本片段，取 `transform[5]`（y 坐标）
2. 将 y 坐标差值 < 3pt 的片段归为同一行
3. 行内按 `transform[4]`（x 坐标）从左到右排序
4. 按 y 坐标降序排列各行（pdf.js 原生坐标系：y 从下到上增大）
5. 拼接为完整文本

### 名称提取（3 层策略）

| 优先级 | 策略                            | 适用版式         |
| --- | ----------------------------- | ------------ |
| 1   | 块级提取：在"购买方信息/销售方信息"块内定位"名称"标签 | 数电票、新版电子票    |
| 2   | 按行提取"名称：xxx"，用"自家公司=购买方"识别    | 旧版无块标题的平铺格式  |
| 3   | 退化为首条=购买方、次条=销售方              | 个人代开等无自家公司场景 |

**lookahead 终止词**（防止名称匹配越界）：  
`名称[：:]` / `统一社会信用代码` / `纳税人识别号` / `身份证号` / `开户行` / `地址` / `电话` / `金额` / `税额` / `价税合计` / `合计` / `备注` / `收款人` / `开票人` / `销售方信息` / `购买方信息` / `销售方` / `购买方` / `项目名称` / `规格型号` / `购销` / `买卖` / `方方` / `信信` / `息息` / `销\s` / `购\s`

### 金额提取（优先级）

1. `合计金额 ¥xx`（数电票不含税金额）
2. `合计 ¥xx`（数电票合计行）
3. `价税合计(小写) ¥xx`（旧版发票含税总额）
4. `价税合计 ¥xx`
5. `¥xx`（兜底取第一个金额）

## OFD 解析原理

OFD（开放版式文档）是数电票的原始格式，本质是一个 ZIP 包：

```
数电票.ofd
├── META/OFD.xml              包描述
├── OFD.xml                   文档结构
└── Doc_0/Pages/Page_0/
    └── Content.xml           页面内容（TextObject + TextCode）
```

解析流程：

1. 用 JSZip 解包，定位所有 `Doc_*/Pages/Page_*/Content.xml`
2. 逐个解析 `<TextObject>`：读取 `CTM` 变换矩阵（6 元素仿射矩阵）
3. 读取子节点 `<TextCode>` 的 `X/Y` 坐标与文本，经 CTM 变换得到页面绝对坐标
4. 按 y 聚合成行（容差 3），行内按 x 排序（OFD 坐标系 y 向下增长，升序即从上到下）
5. 输出与 PDF 提取完全一致的行文本，复用同一套字段解析逻辑

## 本地持久化与筛选统计

- 台账数据自动保存到浏览器 **IndexedDB**（数据库名 `piaoxiaobang`），每次增删改后自动写入
- 启动时自动恢复上次的台账数据（File 原始文件不持久化，恢复后如需打包下载需重新上传）
- 筛选栏支持关键词搜索（号码/销售方/摘要/日期/备注等）与费用分类过滤
- 统计卡实时显示当前筛选结果的张数、金额合计、税额合计、价税合计

## AI 增强流程

```
上传文件 → PDF(文本提取) / OFD(解包提取)
         ↓ 文本为空且配置了 OCR？(仅扫描件)
         PDF 渲染页面 → 腾讯云 GeneralBasicOCR → 拼接文本
         ↓ 配置了大模型？
         大模型校验字段（号码/金额/日期/名称）
         ↓
         规则引擎富化（类型/摘要/分类/备注/文件名）→ 存入台账
```

- 密钥只存本机浏览器 localStorage，识别时直接调用服务商 API，不经过任何中转服务器
- 开通步骤与费用说明见 [腾讯云开通指引.md](./腾讯云开通指引.md)

## 已知限制

1. **摘要长度**：摘要上限 220 字符，超长自动截断
2. **简称长度**：销售方简称上限 6 字符
3. **合并打印**：每张发票只取第 1 页嵌入
4. **打包下载**：从本地存储恢复的台账没有原始文件，需重新上传后才能打包下载
5. **OCR 触发条件**：仅文本提取缺少发票号码时触发（节约免费额度）；开启后扫描件自动识别
6. **发票验真**：暂不支持（需税务接口资质），识别准确率问题可通过手动编辑 + 大模型纠错弥补

### 关键技术修复

**数电票左右两栏布局解析**：  
数电票的"购买方/销售方"是竖排文字，pdf.js 提取后拆成单字散落在文本行里，形成 `购 名称：A公司 销 名称：B公司` 的行。原始正则的终止词没有单独的"销"字，导致第一个名称匹配失败。修复方案是在 lookahead 终止词中增加 `销\s|购\s`（"销"/"购"后跟空格才作为分隔符，避免误伤含"销"/"购"的公司名）。

**摘要表头被过滤**：  
数电票表头 `"项目名称   规格型号   单   位   数   量..."` 被 pdf.js 插入空格后长度达 55+ 字符，触发 `l.length < 50` 阈值被过滤，导致摘要提取起始位置永远找不到。修复方案是移除长度阈值，仅用关键词定位。
